# 侧栏设计

> 一句话：侧栏是**一张地图**，输入框是**工作台**（现在这一段）；
> ★ 地图不再告诉你在哪儿干活 —— 那是工作台的事。

> 范围：侧栏的结构（分区 / 组 / 行 / 菜单）、**文件树形态**、分组与排序规则、会话行与项目行的
> 菜单、「+」与「⋯」的语义、输入框右下角那个项目按钮的两种形态，以及它们和「当前项目」
> 那份真相的关系。
> 不包含：项目表与目录的语义、会话归属与 project root（见 `docs/projects-design.md`）、
> 附件与动效（见 `docs/ui-design.md`）、一轮是什么（见 `docs/runtime-design.md`）。

★ **本文分两半**：§1 讲**代码现在是什么样**（每一条都指得到行），§2 起是**提案 ——
尚未实现**。★ 提案不许混进现状那一半：store 里有动作、界面上没有入口的那种「半个功能」，
是最难查的一种不一致 —— 读代码的人以为它能用，用的人发现它不能用。

## 0. 一句话（目标形态）

★ 侧栏要同时说三件事，而它们是三件不同的事：

| 问题 | 谁回答 | 在哪儿 |
|---|---|---|
| 有哪些对话？ | 会话列表 | 侧栏的行 |
| 它们属于哪儿？ | 项目表（服务端） | 侧栏的组 |
| 我现在在哪儿干活？ | **当前项目**（一份） | ★ 输入框下方的按钮（对话页上是标签）+ `@` 选择器 |

★ 第三件事**只能有一份**。两个控件指着不同的目录，界面就在自己跟自己吵 —— 而
openheron 的「项目」不是标签，是**agent 真正读写的那块目录**：说错一个名字，
model 就在一个目录被告知去另一个目录读写。

★ 提案立三条规矩：

1. ★ **开关只属于「还没决定」的时刻。** 一段对话一旦有了消息，它的项目就定了；
   那时还摆着一个能改项目的控件，是在邀请用户改一件改不了的事。
2. ★ **侧栏不再有项目选择器**（§3.0）—— 切换只剩空视图一处，对话页上**一个项目开关
   都不剩**。
3. ★ **侧栏画成一棵文件树**（§3.5）—— 项目是文件夹，会话是文件，层级一眼看得出。

## 1. 现状

### 1.1 侧栏从上到下四块

| 块 | 是什么 | 在哪儿 |
|---|---|---|
| **New thread** | 放掉当前会话，回到欢迎页 | `web/src/components/sidebar.tsx:41` |
| **项目选择器** | 一个 `<select>`，写「当前项目」 | `web/src/components/sidebar.tsx:59` |
| **分组列表** | 组 = 项目，组下 = 会话 | `web/src/components/sidebar.tsx:81` |
| **设置入口** | 配置文件与密钥 | `web/src/components/sidebar.tsx` 的 `SettingsEntry` |

★ **选择器只在有得选时渲染**（多项目模式且项目表非空）。单项目模式下进程只服务一个
目录，一个只有一项的选择器是装饰。

★ **「New thread」不换项目**：它只把 `activeId` 清空（`web/src/lib/store/actions.ts:339`
`startNewThread`），当前项目原样留着 —— 所以「New thread」永远是「在当前项目里开一段新的」。

### 1.2 组：项目是一组标题

分组是一个**纯函数**（`web/src/lib/projects.ts:97` `groupSessions`）：输入会话、项目表、
作用域，输出组。客户端不决定任何事，它读服务端的答案再画出来。

| 组 | 键 | 什么时候有 |
|---|---|---|
| 置顶组 | `pinned`（`web/src/lib/projects.ts:64`） | ★ **今天永远是空的** —— 服务端还没有 `pinned` 字段（`docs/projects-design.md` §3.4） |
| 项目组 | 项目的 id | 项目表里有它 |
| 未选项目组 | `no-project`（`web/src/lib/projects.ts:67`） | 有会话不属于任何项目 |

★ 三条规则：**空组不画**；**一个会话只在一组里**；单项目模式下**只有一组**（作用域那个），
「未选项目」的会话并进去 —— 进程只服务一个目录，它们无处可去。

★ 表里没有项目时，侧栏是一张**平表**（没有组标题）—— 和项目落地之前长得一模一样。

### 1.3 行：一条会话

一行 = 一条会话：标题、待审批的点、悬停时出现的「⋯」菜单
（`web/src/components/sidebar.tsx:274`）。那个菜单今天**只有两项**：改名、删除。

★ 「⋯」**在行上**就是这一行的菜单 —— 位置是它的身份。会话行的「⋯」是会话的，
项目组的「⋯」（今天还没有）就该是项目的。

★ 这个菜单**不是**组件库的下拉菜单：它是一个手写的 `role="menu"` 的 `div`
（`web/src/components/sidebar.tsx:271`）加一个 `MenuItem`（`web/src/components/sidebar.tsx:297`）。
★ `web/src/components/ui/` 下只有 `button` / `dialog` / `textarea` / `skeleton` / `input` /
`icon-placeholder` —— 这棵树里**没有**下拉菜单结构件。项目行要加菜单，就照这个形状写。

### 1.4 项目行：一个标题 + 一个「+」

组标题是一个 `<h2>`（`web/src/components/sidebar.tsx:92`），它的右边有一个 **「+」**
（`web/src/components/sidebar.tsx:99`），悬停那一行时出现。

★ **「+」是「在那个项目里开一段新对话」**：输入框回到空白，那个项目成为它干活的项目 ——
输入框下方的按钮和 `@` 选择器都跟着说它。

★ **「+」不是切换**：切换（`web/src/lib/store/actions.ts:151` `switchProject`）会**留着**
属于那个项目的会话 —— 输入框是**换进**一个它已经在干活的项目。**「+」从不留着屏幕上那段
会话**，哪怕它就属于这个项目：新会话就是新的，那一段不是它。⇒ 两条规则 ⇒ 两个动作
（`switchProject` 与 `web/src/lib/store/actions.ts:168` `startThreadInProject`），
不是一个带开关的函数。

★ **「+」属于这一组命名的那个项目**，所以判据是**项目表**而不是组键：不是项目的组
（「未选项目」组、置顶组）没有「+」，而一个 id 恰好长得像特殊键的项目**仍然是项目**。

### 1.5 「当前项目」：一份真相

`activeProjectId` 的意思是「**输入框这头在哪个项目里干活**」。今天三个面读它：

| 面 | 读的是 |
|---|---|
| 侧栏的选择器 | `activeProjectId` |
| 输入框下方的按钮（`web/src/components/projects-dialog.tsx:38`） | `selectActiveProjectId`（`web/src/lib/store/selectors.ts:94`） |
| `@` 提及选择器 | 同上 |

★ **屏幕上的会话说了算**：打开一个会话，它的项目就是当前项目
（`web/src/lib/store/actions.ts:268` `openSession`，以及 `web/src/lib/store/actions.ts:230`
`refreshList` —— 启动时会话比列表先到，那一刻它还不知道自己属于哪个项目）。

★ **切换会离开一个属于别的项目的会话**：会话的归属**不可改**
（`api/v2_sessions.go:38` 的 `ProjectID` 只在创建时读，`PATCH` 不接受它）⇒
「切到那个项目」只能是「下一个会话在那个项目里」。判据是纯函数
`web/src/lib/projects.ts:236` `projectSwitch`。

★ **「没有项目」是一个选择**：侧栏有这一项（`web/src/components/sidebar.tsx:65`），
服务端也认（会话落在默认项目根），所以 `web/src/lib/projects.ts:204` `resolveActiveProject`
保留空 id —— 只有 **null**（「还没选过」）才退回第一个项目。

### 1.6 项目能做的事不在侧栏

新建、改名、删除、选目录、切换 —— 全在**输入框下方**那个对话框里
（`web/src/components/projects-dialog.tsx:86`）。侧栏里的项目**只能看**。

★ 写面在输入框下方是有理由的（`docs/projects-design.md` §3.5）：空表时侧栏选择器不渲染，
而空表正是最需要入口的时候。★ 但**读面**在侧栏：项目在那里被看见，就该在那里被操作。

★ 今天那个对话框**既选又管**：点一行是切换（`web/src/components/projects-dialog.tsx:201`
`choose`），每行还带改名（`web/src/components/projects-dialog.tsx:319`）与删除
（`web/src/components/projects-dialog.tsx:333`）两个按钮，底下是新建表单。
⇒ 一个入口扛了两件不同的事，而「切换」那一半在对话页上是错的（§2.2）。

### 1.7 它已经是一棵树，只是没有层级感

★ 组标题是 `<h2>`（`web/src/components/sidebar.tsx:92`），会话列表是它下面的一个
`<ul>`（`web/src/components/sidebar.tsx:110`）—— ★ 结构上已经是「标题 + 子列表」，
也就是树的形状。★ 但今天**看不出来**：没有三角（不知道能不能展开）、没有缩进（不知道
谁是谁的孩子）、没有图标（文件夹和文件长得一样）。★ 所以它是一棵**看不出层级的树**。

## 2. 三个洞

### 2.1 洞一：项目在侧栏里只能看

想在侧栏里改一个项目的名字或目录，得先把目光移到输入框下方、点开对话框、找到那一行。
★ 侧栏是**看**项目的地方，菜单在别处 —— 动作离它被看见的地方太远了。

### 2.2 洞二：对话页上的那个按钮会「切换」

★ 输入框右下角那个按钮（`web/src/components/projects-dialog.tsx:38` `ProjectsButton`）今天
**永远**是开关：点开对话框、点一行就切（`web/src/components/projects-dialog.tsx:201`
`choose` → `web/src/lib/store/actions.ts:151` `switchProject`）。

★ 而一段对话的项目是**定的**：服务端没有把会话搬走的路径（`api/v2_sessions.go:38` 的
`ProjectID` 只在创建时读），所以在对话页上「切到另一个项目」唯一的后果是**离开这段对话**
（`web/src/lib/projects.ts:236` `projectSwitch`）。⇒ 一个写着「切换」的按钮，做的事却是
「把你正在看的东西从屏幕上拿走」—— 名字和后果对不上。

★ 代价还是对称的：openheron 的项目**就是**agent 读写的那块目录，在一个已经有工作的对话上
改项目名，模型就在一个目录被告知去另一个目录读写。

### 2.3 洞三：组不能折叠，层级也看不出来

★ 一个项目下面可能挂着几十段对话（`GET /v2/projects` 的 `sessionCount` 就是这个数，
`api/v2_projects.go:57`）。侧栏今天**每一段都摊开**，没有办法把一个项目收起来；
★ 而「哪些会话属于这个项目」这件事，只能靠「它在那个小标题下面」来猜（§1.7）。

## 3. 提案：职责分家 + 文件树（未实现）

★ 一句话：**选择**归输入框，**管理**归侧栏，**形状**是一棵文件树。

| 控件 | 在哪儿 | 干什么 | 不干什么 |
|---|---|---|---|
| 输入框下方的项目按钮 | 输入框那一行 | ★ 空视图：选下一段对话在哪个项目里干活，**并新建项目**；对话页：只显示这段对话在哪个项目 | 不改一个已有的项目 |
| 项目行的「⋯」 | 侧栏，每个项目一行 | 管理这个项目：新建对话、重命名、改目录、移除 | 不切换当前项目，不新建项目 |
| ~~侧栏的项目选择器~~ | —— | ★ **删掉**（§3.0） | —— |

★ 这张表是这一轮提案的**全部**，其余都是它的推论。

★ **「值」只有一份，「控件」可以有多个**：输入框下方的标签与 `@` 选择器读的是同一个
`activeProjectId`（§1.5）；★ 重复的是**入口**，不是**状态**。

### 3.0 侧栏顶部不再有项目选择器

★ **删掉** `web/src/components/sidebar.tsx:59` 那个 `<select>`（连同它那一格容器）。

理由三条：

1. ★ **它是一个开关，而开关只属于「还没决定」的时刻。** 它今天在对话页上照样能切，
   切的后果是「离开这段对话」（§2.2）。★ 删掉它，切换就只剩空视图一处 —— 对话页上
   **一个项目开关都不剩**，整条规矩才立得住。
2. ★ **它是界面上唯一能选「没有项目」的地方**（`web/src/components/sidebar.tsx:65`
   的 `<option value="">No project</option>`）。★ 删掉它，对话框的列表**必须补上这一项**
   （§3.1）—— 否则「没有项目」就选不到了，而它是一个正当的选择
   （`web/src/lib/projects.ts:204` `resolveActiveProject` 保留空 id）。
3. ★ **它让「当前项目」在界面上有两个显示**：选择器与输入框下方的按钮。★ 删掉它，
   「当前项目」只剩输入框下方那一个地方能看见 —— ★ 界面少一处可能与对话页打架的东西。

★ **副作用**：侧栏顶部只剩「New thread」；项目表为空时侧栏是一张平表（§1.2）。
★ 想换个项目干活 ⇒ **New thread**（或某个项目行的「New conversation」）⇒ 在空视图上选。

### 3.1 输入框下方的按钮：两种形态

★ 判据是**空视图**（`web/src/lib/store/selectors.ts:68` `selectIsEmptyView`）—— 没有对话，
或者对话还没开始（没有消息）。空视图是哪一套界面，由 `web/src/app/shell.tsx:113` 决定。

| 页面 | 形态 | 点了会怎样 |
|---|---|---|
| 空视图（**新建对话页面**） | 按钮 | 打开项目对话框：**选一个**（含「没有项目」），**或建一个新的** |
| 对话页（有消息） | **标签** | 什么都不发生；只显示项目名 |

★ 标签长什么样：文件夹图标 + 项目名 + `aria-label="Project: X"`；`title` 说清楚
「这段对话在这个项目里，对话的项目不能改」。★ 标签形态**不打开对话框**。

★ **「选」与「建」一并完成**：空视图上那一个对话框同时是**选择器**和**新建表单** ——
用户不用先开一个对话框建项目、再开一个对话框切过去。

★ **「没有项目」排在列表的第一项**（`No project`）：它不是某一个项目，它是「**不选**项目」
这一项 —— 排在最后会让人以为它是默认项。

★ **对话页上还能不能换项目？** **不能** —— 那儿一个开关都不剩。
★ 这不是把路堵死，是把路说清楚：一段对话的项目是**定的**；要换项目，就是**另一段对话**。
- 「New thread」（侧栏顶部）回到空视图，当前项目原样留着 → 在那儿改；
- 项目行的「New conversation」在这个项目里新起一段 → 它就成了当前项目。

### 3.2 项目行的「⋯」菜单

★ 菜单分两组，中间一条分隔线：**第一组动项目自己，第二组动项目里的东西**。

| 组 | 项 | 做什么 | 现状 |
|---|---|---|---|
| 项目 | **新建对话** | 在这个项目里新起一段对话 | ★ **有**：动作是 `startThreadInProject`（`web/src/lib/store/actions.ts:168`）—— ★ 界面入口是组头的「+」，★ **它并进这个菜单**（§9） |
| 项目 | **重命名** | 改项目的名字 | ★ **有**：`PATCH /v2/projects/{id}` 收 `name`（`api/v2_projects.go:177`），store 有 `renameProject`（`web/src/lib/store/actions.ts:194`）—— ★ 只差界面 |
| 项目 | **修改目录** | 改项目指向哪个目录 | ★ **接口有**（同一个 `PATCH` 收 `root`），★ **客户端没有这个动作** —— 要新写一个 store 动作 |
| 项目 | **移除项目** | 从侧栏摘掉这个项目 | ★ **有**：`DELETE /v2/projects/{id}`（`api/v2_projects.go:225`）、`deleteProject`（`web/src/lib/store/actions.ts:204`）—— 入口在对话框里 |
| 内容 | **归档这个项目的对话** | 把项目里的会话收起来 | ★ **没有**：会话只有删，没有归档状态 |
| 内容 | **在文件夹中显示** | 用系统文件管理器打开项目目录 | ★ **没有**：反方向那一半有（`POST /v2/fs/pick-directory`，`api/v2_dirpick.go:59`） |

★ **菜单里没有「新建项目」**：新建只在空视图那个对话框里完成（§3.1）——
一个动作一个地方。

★ **重命名就地做**：组标题变成一个输入框，形状跟会话行改名一样
（`web/src/components/sidebar.tsx:210` 那一段）。
★ **修改目录要一个小对话框**：路径输入 + Browse（复用 `pickDirectory`，
`web/src/lib/store/actions.ts:218`）—— ★ 路径得问跑服务端的那台机器，浏览器给不了绝对路径。

★ **菜单的形状照会话行走**：手写的 `role="menu"` 的 `div` + `MenuItem`
（`web/src/components/sidebar.tsx:271` / `:297`）—— ★ 别为了一个菜单引进一个依赖。
★ 菜单要**点外面就关**（会话行今天是这么做的，`web/src/components/sidebar.tsx:146`）——
项目行的菜单照做，不然两个菜单会同时开着。

★ **「在文件夹中显示」在 openheron 里比参考实现里更必要**：参考实现里的项目是个虚拟容器，
它是锦上添花；而这里**项目就是目录**，agent 就在里面读写，用户核对「它到底在哪儿干活」
只有这一条路。★ 而且它和 `pick-directory` 是同一件事的两头：同一台机器、同一个理由 ——
**浏览器打不开本机的文件夹管理器**，所以都得服务端做。

★ **「移除项目」的代价比看上去大**：在 openheron 里**项目就是目录**，摘掉标签之后那些会话
回落成「未选项目」、改在**默认项目根**里干活。★ 菜单上要写清楚（「会话留着，它们改在
默认项目根里干活」），而不是让人以为历史没了。

### 3.3 写面分两半：新的在空视图，已有的在侧栏

★ 删除选择器之后，「新建项目」**没有地方放**了 —— 侧栏顶部不再有一张项目的列表可挂
一个「+」。而它**也不该**塞进某个项目的「⋯」：一个项目都没有的时候，没有菜单可挂，
而「还没有项目」正是最需要入口的时候。

⇒ ★ **分界线是「新的」与「已有的」**：

| 动作 | 在哪儿 | 为什么 |
|---|---|---|
| **新建项目** | 空视图那个对话框（§3.1） | ★ 它是「决定下一段对话在哪儿干活」的一部分 —— 属于「还没决定」的那一刻 |
| **改名 / 改目录 / 移除** | 侧栏项目行的「⋯」（§3.2） | ★ 它动的是**已经在地图上的东西** —— 地图上看见的，就该在地图上改 |

★ 两半都在该在的地方：新的在**决定之前**，已有的在**地图之上**。
★ 顺带解决了原来那个洞（§2.1）：项目在侧栏里被看见，就能在侧栏里被改。

### 3.4 组标题的折叠

★ 组标题左边一个三角，点标题或三角就折叠/展开这一组（形状见 §3.5）。

★ **折叠的组仍然画标题** —— 它下面还有东西，只是收起来了。★ 这一条跟「空组不画」
（`web/src/lib/projects.ts:97` `groupSessions`）是**两条不同的规矩**，别混：空组是真的
没有东西，折叠组是有东西但没摊开。★ 折叠后标题上要写清楚数量（`sessionCount` 服务端已经
给了，`api/v2_projects.go:57`），不然「这个项目有 12 段对话」这条信息就丢了。

★ **折叠状态是偏好，不是事实**：它跟侧栏自己能不能折叠一个待遇
（`web/src/app/shell.tsx:16` 的 `SIDEBAR_KEY`，写 localStorage）。★ 记住的是**组键**
（项目 id、`no-project`、`pinned`），不是项目 id —— 那个「没有项目」的组也要能被记住。
★ 项目被删了，那个键就永远留在记住的集合里 —— 读回来时把**不存在的组键**滤掉。
★ 新项目默认展开（不在记住的集合里 = 展开）。

★ **判定写成纯函数**，放在 `web/src/lib/projects.ts`（比如 `foldGroups(groups, folded)`）——
这样能 `bun test`，不用开浏览器。

### 3.5 侧栏画成一棵文件树

★ 侧栏本来就已经是树的样子（§1.7）—— 只是今天它是一棵**看不出层级的树**。★ 文件树的
好处是**层级一眼看得出**，而且它是一套人人认得的形状：文件夹可以展开，里面是文件。

```
▾ 📁 MyProject                       ⋯
      Conversation A
      Conversation B
▸ 📁 OtherProject                    ⋯
▾ 📁 No project
      Loose chat
```

六条：

1. ★ **三角**：组头最左一个 `ChevronRight` / `ChevronDown`（`lucide-react` 里都有），
   点它或者点组名都折叠/展开这一组。★ 三角的朝向**就是**这个组的状态，不需要另一个标记。
2. ★ **文件夹图标**：三角右边一个 `Folder`，展开时换 `FolderOpen` —— 文件树里
   「打开的文件夹」是经典信号。
3. ★ **缩进**：会话行往右缩一级（≈1rem）。★ 缩进是树的主要语言：没有缩进，三角和图标
   只是装饰。
4. ★ **会话行不加文件图标**：它有标题、有待审批的点、有悬停菜单。★ 三十个会话配三十个
   图标会把地图糊掉 —— 层级靠**缩进 + 父行的文件夹**表达就够了。
5. ★ **「我在哪儿」由位置回答**：被高亮的那一行会话就坐在它所属的文件夹里。★ 所以
   **文件夹不需要**再标一个「当前」—— ★ 那会是第二处「当前项目」的显示（§3.0 刚删掉它）。
6. ★ **没有项目的时候是一张平表**（§1.2）：那时没有文件夹行，也没有三角，就是一列会话 ——
   ★ 文件树在根下放文件也是这个样子。

★ **「No project」那个组也是一个文件夹**，它可以折叠、可以记住；但它**没有**「⋯」
（它不是一个项目，没有名字可改、没有目录可换）—— ★ 和它今天没有「+」是同一条理由。

★ **读屏要按树播报**：这个侧栏要变成 `role="tree"` / `role="treeitem"` /
`aria-expanded` / `aria-level`（子列表用 `role="group"`）。★ 一堆缩进了的 `div` 读起来
是一堆字，不是树 —— ★ 「像文件树」不能只是**长得像**。
★ 这一步会改既有元素的语义 ⇒ Playwright 里按角色找元素的地方要跟着看一眼。

★ **键盘是独立的一步**（§8 的 S5）：↑↓ 在**看得见的**行之间移动，←→ 折叠/展开，
Enter 打开。★ 今天是 Tab 顺序，一个项目 30 段对话要按 30 次 Tab。

### 3.6 会话行的菜单要不要补

会话的「⋯」今天只有改名和删除。★ **归档**如果落地，两边都该有（项目菜单里是「一次归档
这个项目的全部」，会话菜单里是「归档这一段」）；★ **「在文件夹中显示」是项目级的动作**
（会话没有自己的目录 —— 它在项目的目录里），所以不进会话菜单。

## 4. 排序与折叠

★ 侧栏上会同时出现四种排序，别把它们混成一件：

| 排序 | 谁定 | 落在哪 |
|---|---|---|
| 项目之间的先后 | `projects.json` 里的 `order`（`projects/projects.go:62`） | `web/src/lib/projects.ts:169` `sortProjects` |
| 组之间的先后 | 置顶组 → 项目组（按 order）→ 未选项目组 | `web/src/lib/projects.ts:97` `groupSessions` |
| 组内会话的先后 | 服务端的会话列表 | 服务端 |
| 「我在这儿」 | **当前项目** | §1.5 |

★ **「我在这儿」不是第四种排序**，它是**高亮**：一段会话属于哪个项目是表里查出来的
（`api/v2_projects.go:125` `projectIDOf`），客户端不决定。⇒ 高亮的位置永远跟着组走，
高亮的内容永远来自表。

★ **折叠也不是排序**：它不改变组的先后，也不改变组内会话的先后 —— 它只决定**画不画那些行**。
★ 折叠状态是**本地**的，服务端不知道。

## 7. 风险与边界

| 风险 | 为什么会疼 | 怎么挡 |
|---|---|---|
| ★ 删掉选择器 ⇒「没有项目」选不到了 | 它今天是界面上唯一能选这一项的地方 | ★ 对话框的列表补上 `No project` 并**排第一**（§3.1），点它走 `switchProject("")` |
| ★ 对话页上没有任何项目开关 | 用户在对话里想换个项目干活 | ★ 这是**有意的**：一段对话的项目是定的；换项目 = 另一段对话（New thread / 项目行的「New conversation」） |
| 侧栏里出现第二个「当前项目」 | 两个控件指着不同目录 ⇒ 界面自己跟自己吵 | ★ 「当前项目」只有 `activeProjectId` 一份（§1.5）；★ 删掉选择器后，界面上只剩输入框下方那一个显示；★ 树里也**不给文件夹**加「当前」标记（§3.5 第 5 条） |
| ★ 写面搬家中间有一段两边都不能管 | 项目变得没法新建、改名 | ★ S2 是一整块（§8），中间不留窗口 |
| ★ 菜单项和它作用的对象不是一层 | 「归档对话」和「移除项目」挨着，看着一样重 | ★ 分组：第一组动项目，第二组动项目里的东西 |
| 「归档」被当成「删除」 | 两个后果差一个量级 | ★ 归档是「移走但还在」；界面要写清楚 |
| 折叠的组被「空组不画」吃掉 | 折叠后组里没行，标题也不见了 | ★ 两条规矩分开：空组不画，折叠组**照画标题**（§3.4） |
| ★ 菜单开在滚动容器里，靠下时被裁掉 | 菜单是 `absolute` 的，容器是 `overflow-y-auto` | ★ 菜单在组头**上方**展开（`bottom-full`），或者干脆跟会话行一样接受被裁 —— ★ 今天会话行的菜单就有这个边界，先不修 |
| ★ 换 `role="tree"` 改掉了既有语义 | Playwright 里按角色找元素的地方会变 | ★ 跟 S3 一起改，spec 跟着调 |
| 新字段把老的表读坏了 | 表在用户的数据目录里 | ★ 加字段必须能读老表 |
| 悬停才出现的入口没人发现 | 入口存在但看不见 | ★ 会话行的「⋯」已经是这个规矩；★ 三角是**常驻**的（它说的是状态，不是动作） |
| 侧栏塞太多控件 | 每加一个控件，地图就更难读 | ★ 一个组头最多三个：**三角 + 文件夹 + 名字**（点名字即折叠），加**一个**「⋯」 |

## 9. 已定的取舍

| 取舍 | 决定 | 为什么 |
|---|---|---|
| 组头的「+」并进「⋯」？ | ★ **并进** | 「一个动作一个地方」；组头于是只有「三角 + 文件夹 + 名字 + 一个「⋯」」；★ 与会话行同形（会话行是「标题 + ⋯」，项目行是「▾ 名字 + ⋯」），侧栏只有一种菜单形状。★ 代价：最高频的动作从一键变成两键 |
| 「没有项目」在对话框列表里排哪？ | ★ **排第一** | 它是「**不选**项目」这一项，不是某一个项目；★ 排在最后会让人以为它是默认项 |
| 折叠要不要记住？ | ★ **记住**（localStorage，键 `openheron.sidebar.folded`，存组键的 JSON 数组） | 跟侧栏自己的折叠一个待遇（`web/src/app/shell.tsx:16`）；★ 项目被删了要把那个键滤掉 |
| 侧栏的项目选择器？ | ★ **删掉** | §3.0 |
| 侧栏长什么样？ | ★ **文件树** | §3.5 |
| 会话行要不要文件图标？ | ★ **不加** | 缩进 + 父行的文件夹已经说清了层级；★ 三十个会话配三十个图标会把地图糊掉 |
| 折叠状态要不要跨设备？ | ★ **不要** | 它是**本机的偏好**，写进 localStorage 就够 |
| 「折叠全部 / 展开全部」要不要？ | ★ **不要** | 一个组一个三角已经够了；★ 树里再加一个总开关是第四个控件 |

★ 这一轮**没有待决项**了 —— 上面 §9 的九条都定了。

★ 但有**两个已知的边界**留给下一轮，它们不是这一轮的事：

## 11. 不在范围内

| 不做 | 为什么 |
|---|---|
| 会话拖拽排序 / 拖拽换项目 | 顺序是服务端给的，归属不可改（`docs/projects-design.md` §2.3）；客户端改它就是第二份真相 |
| 项目的自由嵌套（项目里有项目） | 项目**就是目录**，目录不套目录；层级留给「分区」那一层扁平结构 |
| 会话在项目之间搬家 | 归属不可改（`docs/projects-design.md` §2.3）；「换项目 = 新建项目」 |
| 一个项目一个配置树 | 配置是**一份**的，所有项目共享（`docs/projects-design.md` §10） |
| 侧栏里的搜索 / 过滤 | 那是会话列表的事，和分组是两条轴 |
